2.10 社区形成后的开源、自部署节点与 Ankora Mesh

本节做什么：接上 2.9 的经营节奏——平台社区形成后（后期设想），平台核心源码公开（禁止商用）。开源协议允许任何人自部署、成为网络节点、设置节点 GM、自行定义节点本地 schema 与规则；但不允许把平台自身用于盈利。公司的盈利点因此全部收到平台外围的信息化服务；节点之间可以有结构化的信息互通通道，即 Ankora Mesh。

时机：经营节奏的第三步，不是能力开关：第一步社群自转（2.9）→ 第二步公司对外提供准入与持续运营托管（2.9）→ 第三步社区形成后开源。开源前后平台四件事、订阅 / 不订阅、零算法、无界面 / 无引导流、两类库、运行域 / 业务域隔离完全不变；这也不是 A / B / C 阶段切换或阶段判据（2.6 / 6.9 / 8.3）。最关键的一层区分：第 6 章与 2.2 / 6.7 / 8.3 的禁令是 Ankora 本地平台的硬约束，永久不变；开源协议是对使用方的软约束，不靠本地平台运行时强制。

项开源前（社区形成前）开源后（社区形成后）
平台核心代码单一运营方运维，未公开按开源协议公开，任何人可自部署、可审计、可自行运维
许可证不适用禁止把平台自身用于盈利：不作价、不授权收费、不设商业许可 / 双授权、不卖节点资格或 Mesh 接入权；具体许可文本与 non-commercial 边界列 10 章待定
平台自身收入5.5 的内测期资源档位（推送连接数 / 投递量 / 中继带宽）与公司外围服务平台核心不作价、不再以资源档位向用户售卖；配额成为节点本地的技术配置，由节点运营者自行设定（开源后 entitlement 的最终处置列 10 章待定，5.5 / 5.12）
公司收入2.9 准入与持续运营托管服务费全部来自平台外围的信息化服务（见下），收的是人的劳动，不是代码或许可
协议恒定项四件事、二元操作、零算法等（2.6 / 6.9）逐条不变；开源只改代码的可见性与部署主体，不改协议
约束性质第 6 章全部禁令 = 本地平台硬约束，实现时逐条自查本地平台硬约束逐条不变；开源协议对使用方是软约束（许可文本 + 社区约定），不靠运行时强制、不做合规扫描 / 认证 / 白名单（2.10 / 6 章）

自部署节点与节点 GM：任何人按开源协议自部署一份平台核心，即成为一个网络节点；节点运营者自己生成本节点的节点 GM 密钥并自行发布公钥。节点 GM 与 2.8 的创世 GM 必须分域：

维度创世 GM（2.8）节点 GM（本节）
身份创世 gm_identity_hash 协议常量，全网唯一、随协议版本分发节点运营者自签自发布，只在本节点有效；不进创世常量、不由平台签发
签什么全网协议运行通知：补丁 / schema / 节点 / 安全 / 规则变更，走固定槽位本节点本地的 schema 版本、本地运行规则变更与节点公告
谁校验所有 AKA 本地持有常量、可离线校验订阅该节点的 AKA 自行配置信任、自行核对公钥，可随时退订换节点
明确不做不进业务分发、不参与业务信息市场不签全网运行通知、不冒充创世 GM、不改协议原语、不获得全网分发优势；Mesh 互通时其签名不作为加权或排序依据

节点可以自定义什么：本地板块 JSON Schema、本地采集 / 过滤 / 去重规则、本地 TTL 上限、本地资源配额与接入规则、本地公告、节点 GM 轮换，以及节点内部要不要提供界面、要不要引入本地排序规则、要不要与其他节点互认——这些由使用方自行决定、自行承担。「遵循开源协议」是面向使用方的软约束：靠许可文本与社区约定，要求保留协议互操作基线（验签、订阅 / 不订阅、TTL、payload 结构、原始事实可溯源）并禁止把平台自身用于盈利；不靠 Ankora 运行时强制，不做合规扫描 / 认证 / 白名单。使用方的自定义不回流到 Ankora 本地平台，也不改变第 6 章对本地平台的硬禁令；Ankora 不背书、不保证兼容、不因此调整自己的采样或可见性。两类不属于软约束的硬事实：不得伪造 / 替换他节点事实的签名与 content_hash（密码学可验），以及节点 GM 公钥不进创世 gm_identity_hash 常量（协议规范）。判据：删掉任一节点，Ankora 本地平台的协议行为零变化；使用方节点内部怎么改，都不是 Ankora 的能力或承诺。

Ankora Mesh：节点之间可选的信息互通通道：

项口径
定位节点之间双边 / 多边自愿的结构化事实互通，是协议外的互联约定；不是 Ankora 平台功能、不进 6.1 能力清单、不新增 9.1 / 9.2 平台接口，通道端点与格式列 10 章待定；Ankora 本地平台只作为一个自愿节点参与，不做 Mesh 治理、不维护节点目录、不做全局互认
只互通什么带签名、source、content_hash、TTL 与采集声明版本摘要的原始事实；接收节点自行验签、自行决定是否纳入本地板块。Ankora 本地平台一侧只发送 / 接收原始事实；其他节点之间传什么由双方自行约定，属使用方自治
本地平台一侧不互通什么行为数据、点击 / 曝光、订阅者名单、用户画像、评分 / 排序结果；Ankora 本地平台永不采集行为数据（2.5），也不传「谁更该被看到」。其他节点之间传什么属使用方自治，Ankora 不背书、不治理、不做合规扫描（软约束，2.10）
订阅关系互通只让事实可达：订阅方 AKA 仍须主动订阅目标节点，不自动扩散订阅、不产生全平台分发优势；双方可随时断开通道；本地平台侧不因通道关系改变采样概率、TTL 或可见性排序（使用方节点内部规则属自治，Ankora 不背书）
与 W3 禁令的关系2.2 / 6.7 / 8.3 的禁令原样保留，只约束 Ankora 本地平台：不引入联邦、多节点互认或任何 W3 式去中心化。开源后使用方节点之间的自愿互通属使用方自治（软约束），不构成 Ankora 平台的联邦化，也不需要新的全局身份层；互通基于既有 AKA 公钥验签（2.2 / 2.10）
# Ankora Mesh 通道上只允许出现原始事实，不出现评价与画像
mesh_fact:
  publisher_agent_id: <原始签名者 AKA 公钥哈希>
  signature: <原始签名者的签名，不替换、不代签>
  content_hash: ...
  source: { url: <原文地址>, published_at: <ISO8601> }
  expires_at: <ISO8601>            # 接收节点同样到期即删、410 Gone
  collection_policy_version: ...
# 不携带：点击 / 曝光 / 订阅者名单 / 画像 / 评分 / 排序位次 / 节点 GM 权重
# 接收节点：先验签再决定要不要纳入本地板块；平台核心不因 Mesh 获得分发权

盈利点全部在平台外围的信息化服务：开源之后，公司不靠平台代码、许可、节点资格、Mesh 通道或分发赚钱，只卖人的劳动：2.9 的准入与持续运营托管（建 AKA、schema、采集声明、TTL 重发、SLA），以及开源核心的自部署与运维托管、节点 GM 配置与密钥轮换代办、节点本地 schema / 规则定制、Mesh 通道配置与验签 / 声明对齐、企业既有系统（RSS / API / 内部库）到结构化锚点的集成、版本升级与补丁跟进、培训与规则咨询。客户免费拿到代码，付的是服务费；随时可以拿走代码与数据自行运维。服务费与曝光、点击、订阅人数、交易额、节点数量、Mesh 流量全部脱钩，账单留在公司独立账目、不进身份库（2.3 / 2.9 / 5.12 / 6.5）。

否定清单：

  • 不卖平台自身：不售软件许可 / 商业授权 / 商标 / 认证，不设「官方节点」白名单、不收节点准入费或 Mesh 接入费、不卖通道优先权；
  • 本地平台禁令不因开源放宽：第 6 章逐条不变；不新增 Ankora 平台能力、接口、角色枚举或全局身份层；开源协议对使用方是软约束，使用方的节点自定义不回流、不进 6.1 能力清单；
  • Ankora 本地平台侧不把 Mesh 做成算法：不排序 / 推荐 / 加权 / 置顶，不做跨节点热度、信誉或榜单，不因通道关系改变采样概率或 TTL；其他节点内部的规则属使用方自治，Ankora 不背书、不参与；
  • 不让节点 GM 越域：节点 GM 不签全网运行通知、不冒充创世 GM、不获得业务分发特权，Mesh 里其签名不作为权重；
  • 不把开源协议当平台运行时强制：不做合规扫描、不发认证标记、不维护节点白名单、不因使用方自定义而调整本地平台；「遵循开源协议」由许可文本与社区约定承载（软约束）；
  • 不把外围服务做成门槛：不因客户没买服务限制自部署、限制互通或降低配额；有 AKA 的自助免费仍是缺省（2.9 / 5.12）。

三个必须先说清的风险：

风险说明处理口径
开源被读成 W3把自部署节点 / Mesh 写成去中心化、联邦或共识网络，2.2 与 6.7 的禁令失效本地平台禁令原样保留、不因开源放宽；开源只改代码可见性与部署主体；使用方自治不等于 Ankora 联邦化，v0.3 推论仍撤回

盈利回潮到平台开源后仍按许可、节点资格、档位或 Mesh 流量收费，或把外围服务做成平台功能许可证禁盈利 + 服务费只按人的劳动计价 + 独立账目；判据「钱是付给人的服务，还是付给平台代码 / 权限 / 曝光」
边界：开源改的是代码的可见性与部署主体，不是协议的能力清单，也不是盈利主体。本地平台禁令是硬约束，开源协议是使用方软约束：前者写进第 6 章、实现时逐条自查，后者靠许可文本与社区约定、不做运行时强制；两者不得互相替换。判定越界只需问一句——「钱是付给人的外围信息化服务，还是付给平台代码 / 节点资格 / 通道优先权 / 曝光？」后者即同时违反开源协议与第 2 章四条宪法。收编红线：把 Mesh 写进平台服务端、给节点 GM 全网签名权、按节点或流量收费、或以「遵循开源协议」为名要求全网一致执行某节点的本地规则，都不走阶段例外（2.6 / 6.9）。

来自 2.2 商业化边界

Ankora 是一个商业化的网络，不是去中心化协议或联邦网络。 社区形成前平台由单一运营方负责运维与计费；社区形成后平台核心按开源协议公开，任何人可自部署成为网络节点（2.10）。用户始终以 AKA ID 接入；不做 W3 式的技术／经济／法律去中心化，不引入链、代币，也不要求多节点互认。v0.3 的去中心化推论已整体撤回。以上第 6 章及本节的禁令约束的是 Ankora 本地平台，硬约束永久不变；社区形成后平台核心开源，开源协议对使用方是软约束，自部署节点内部的自定义不回流、不构成 Ankora 平台能力（2.10 / 6 章）。

  • 控制面认证节点、下发凭证、维护健康心跳；开源后每个自部署节点自行运维本节点的控制面，凭证与健康列表不再是单一运营方的专属能力；节点是否信任其他节点由运营者自行配置（属使用方自治）；Ankora 本地平台控制面仍不做全局互认、不维护全网节点目录（2.10）；

不属于节点的东西：创始人自营服务端上跑的创始 AKA（GM）不是 Ankora Relay 节点，不由平台托管或下发凭证、不进健康列表；用户本地的 AKA 与 SDK 同理。平台节点对业务域请求只认协议调用，不因运营称谓给任何一侧特殊路由；运行域固定槽位由协议常量定义、所有 AKA 本地可验，也不是节点侧的特殊路由（2.8 / 6.2）。

每一步只在前一步成为瓶颈时才做。A → B → C 扩大的是铺开范围、板块开放顺序与推广覆盖人群，不是平台的功能清单；全程永久不引入算法、传播干预或引导流，也不引入联邦、多节点互认或任何 W3 式去中心化（2.2 / 2.6）。开源协议对使用方是软约束，本地平台禁令不因开源放宽；社区形成后开源与 Ankora Mesh 事实互通属经营节奏与节点自愿互联，不进阶段能力清单（2.10）。

来自 9.4 SDK 不提供什么

  • 9.1 / 9.2 之外的任何新平台接口、官方客户端、默认订阅、新手引导与「装好就能用」的上手流程；默认值里仍不含 GM 的业务 board_id 或任何 onboarding 状态字段，是否读它的入门说明由用户 AKA 自行决定。唯一例外是 2.8 的创世协议常量——协议自检所需，不是订阅、不是视图、不是引导（2.8 / 9.4）。开源后同样不预置节点列表、不推荐 / 排序节点、不自动信任节点 GM：连哪个节点、信任哪把节点公钥由用户 AKA 自行配置（2.10）。
