01 · What It Does

从“每天找信息”变成“每天自动筛信息”

系统围绕一组固定业务关注点运行，自动检索多个公开信息源，使用大模型抽取结构化字段，并生成面向业务人员阅读的日报。

多路召回

同时使用目标来源路线与区域路线召回候选结果，减少单一路径带来的遗漏风险。

AI 结构化清洗

把非结构化网页摘要转为统一 JSON，包含发布时间、采购主体、代理机构、预算、截止时间、相关度、理由与摘要。

日报发布

自动渲染 Markdown 日报，写入团队知识库；正文避免重复标题，信息字段保持紧凑、可读。

历史记忆库

用本地 SQLite 保存原始召回和清洗结果，支撑去重、模式切换、追溯和后续 Excel 镜像。

即时通知

每日任务完成后通过既有消息网关发送运行结果；若发现新信息，会在通知中突出标注。

可演进策略

初期宽召回，稳定后根据重复率自动收窄范围，把 token 和搜索成本留给真正的新信息。

02 · Architecture

轻量后端优先，而不是先做配置大平台

这个 MVP 的工程判断是先打通真实业务闭环。搜索、抽取、存储、发布、通知都用清晰的小模块组织，避免在验证价值前过早建设复杂前端。

01 计划任务Windows 定时任务或手动命令触发每日流程。
02 搜索召回调用通用搜索 API，按多条检索路线获取候选。
03 去重合并按标准化 URL 和标题归并重复候选。
04 LLM 抽取通过兼容式大模型接口输出严格 JSON。
05 持久化原始结果、清洗结果、运行状态写入本地库。
06 发布通知生成日报，发布到知识库，并发送消息通知。
技术取舍：把“召回来源”和“实际链接来源”分开保存。日报只展示短来源，审计字段保留在 JSON 和 SQLite 中。
03 · Data Model

数据沉淀比单次日报更重要

日报解决当天阅读，数据库解决长期判断。系统把每次召回与清洗结果都落地，后续可以扩展为本地 Excel 镜像、检索面板或稳定运行分析。

原始召回表

  • 记录查询路线、目标来源、候选标题和 URL。
  • 保存搜索返回的原始摘要和发布时间。
  • 通过标准化 URL 维护首次出现和最近出现日期。

清洗结果表

  • 保存统一字段 JSON，支持日报重渲染。
  • 保留相关度等级和评分，便于筛选。
  • 支撑历史 3 天、7 天或更长窗口的回看。

04 · Automation Strategy

从宽召回到稳定模式的自动切换

刚启动时，系统倾向于多路宽召回，优先避免漏掉关键信息。运行一段时间后，如果数据库显示每日召回高度重叠，系统会自动切换到更省 token 的稳定模式。

启动阶段

  • 使用更宽的时间窗口。
  • 双路线召回候选。
  • 用 AI 清洗过滤非目标区域和非相关信息。

稳定阶段

  • 先与本地库比对，剔除高度重复内容。
  • 只把新增或不确定候选喂给模型。
  • 日报包含近期历史记录和当日新增。

故障闭环

  • 运行日志写入本地文件。
  • 成功和失败都可通过消息网关通知。
  • 输出 JSON 支持重渲染与重新发布。
05 · Technical Stack

尽量少的依赖，清楚的边界

系统用标准脚本和小型服务模块组合，不绑定某个不可替换的云产品。所有凭证通过环境变量注入，代码只保留稳定的模块边界和接口契约。

  • Runtime: Python command workflow
  • Search: Generic web search API adapter
  • LLM: OpenAI-compatible chat completion endpoint
  • Storage: Local JSON artifacts + SQLite database
  • Publishing: Knowledge-base document API
  • Notification: Existing chat gateway integration
  • Scheduling: Native Windows scheduled task
  • Testing: Unit tests for render, workflow, storage and publishing
06 · Extension

可复用的业务配置边界

这套链路的核心价值在于把“固定关注范围 + 自动召回 + 结构化判断 + 报告发布”拆成可替换模块，便于迁移到其他垂直信息监测任务。

业务侧可替换

  • 关注主题和关键词组。
  • 目标来源和区域规则。
  • 结构化字段 schema。
  • 日报模板和排序策略。
  • 通知渠道和消息摘要格式。

工程侧保持稳定

  • 端到端链路设计。
  • 数据落库和去重策略。
  • 日报格式演进思路。
  • 自动化运行和通知闭环。
  • 公开 API 边界下的工程取舍。

适合复用到更多垂直信息雷达场景

替换目标来源、关键词、抽取 schema 和发布出口后，可以扩展到政策跟踪、行业招采、竞品动态、标准规范更新等场景。
