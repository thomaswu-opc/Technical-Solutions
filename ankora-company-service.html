公司服务与商业方案

公司是平台之外的独立经营主体，直接向 to C / to B 客户卖准入与持续运营托管服务并自收款；协议层零感知、不新增角色与接口。有 AKA 的用户自助免费（缺省档位），付费只买代客劳动，不买平台权限。「先自转、后服务」是经营节奏设想，不是承诺、不是阶段能力开关。

2.9 公司的准入与持续运营托管服务：先让社群转起来

本节做什么：把 2.3 的「企业服务」写成一项具体、可收费的业务——公司帮客户跨过 Ankora 的高准入门槛：创建并配置自己的 AKA，之后持续代客运营。经营顺序是先让社群自己转起来，再把这套能力对外卖成服务。一句话分界：有 AKA、能自己搞定的，自己免费用；不懂这套、没有 AKA 的，公司提供建设与托管服务。主体仍是公司作为独立经营主体直接向客户提供的 to C / to B 服务——不是平台服务端的能力，也不是网络里某个「服务商 Agent」角色；公司自己定价、自己收款。交付的锚点随 Head 更新自动形成带 source.url 的结构化可订阅信息，不做算法推流、不搬运内容。

先自转，后服务（经营节奏设想，不是承诺、不是能力开关）：

顺序做什么为什么
第一步 · 社群自转线下 AI 社群里已有 AKA 的深度用户自己创建板块、自己订阅、自己写采集规则、自己验签与按 TTL 重发（2.6 / 2.7 / 场景 E）；公司此阶段只作为普通参与者，不对外卖建设服务先验证真实供需与高纯净信息共享能自转；门槛本来就是内生的，社群由能自助的人构成
第二步 · 对外提供准入与托管社群转起来后，公司把「帮人跨过门槛 + 持续运营」产品化，向没有 AKA / 不懂这套的 to C 个人与 to B Head 提供建设与托管服务并收费服务是对已有网络需求的响应，不是拉新入口；避免它被读成「平台降门槛流程」或增长工具（2.6 / 6.3）
两步前后恒定平台四件事、订阅 / 不订阅二元操作、无界面 / 无引导流、两类库，完全不变这是经营与推广顺序，不是 A / B / C 阶段切换、不是能力开关；服务从来不是「到某阶段才解锁」的平台功能，也不构成阶段切换判据（2.6 / 6.9 / 8.3）

准入门槛具体高在哪：门槛来自用户自身一侧的能力事实，不是平台发放的资格——要自己持有并保管密钥与 AKA 分身、定义板块 JSON Schema、写采集与筛选策略、做验签与 content_hash 去重、维护采集声明版本、按 TTL 到期重发、管理订阅 / 退订与本地抓取策略、必要时配置 POST /connect。这些正是公司代客做的事。平台不认证「谁够格」、不邀请、不评级，也不因此新增任何功能（2.7 / 6.3）。

词是什么能不能收钱
平台（Ankora 协议服务端）只做四件事、两类库、headless；不采集、不转换内容、不托管正文不收服务费、不经手钱；只挂 entitlement 资源档位（5.5）
公司（运营主体）平台之外的商业实体，社群自转后对外卖准入与持续运营托管服务；与客户签服务合同、自收款能收：收自己的服务费，账目独立于分发层、不进身份库（2.9 / 5.12）
客户 AKAto C 的个人 / AKA 拥有者，或 to B 的 Head / 信息流量主；AKA ID、密钥与板块归客户自己决定是否购买；不买也能完整使用网络，付费不产生任何分发优势或权限（6.2）

「平台不插手钱」的准确范围：它只约束协议服务端——平台不代收、不经手、不抽成、不分成、不设结算通道，也不接触他人的订阅者名单与收入数据（2.3 / 6.5）。公司卖自己的服务并自收款不在此列：那是经营主体与客户之间的普通商业交易，不是平台以分发层身份介入他人交易。两者一旦混同，就会退化成「平台收流量费」，四条宪法当场失效。

两条路径，同一套协议：

路径谁来做付费平台看到什么
自助免费已有 AKA、能自己搞定上述门槛的用户，自己创建与运营免费：这是所有 AKA 的缺省资源档位，不存免费用户名单，不做「有没有 AKA / 懂不懂」的资格审查（5.5 / 5.12）普通验签请求；无法区分是谁在自己做
建设 + 持续运营托管没有 AKA 或不懂这套的客户，委托公司创建 AKA 并长期代客运维付公司的服务费（建置 + 持续运营），公司自收款仍是同一个客户 AKA 的普通验签请求；平台不识别服务关系、不给任何档位或分发变化

付费买的是代客劳动，不是平台权限：购买服务不改变 entitlement 档位、不解锁功能、不改变采样概率、TTL、可见性或投递顺序；免费自助与托管客户在协议里完全同权。判据：把 publisher_agent_id 换成任意其他信息主，协议行为与可见性零变化。

托管 = 建设 + 持续运营，不是一次性交付：

  • 建设（准入）：创建并配置客户自己的 AKA ID 与密钥、板块 schema、订阅与本地抓取策略、采集声明与字段映射；由客户 / Head 主动委托，授权链条写进声明（5.9）；
  • 持续运营：按官方 RSS / release / 授权 API 的更新做确定性字段映射与签名发布、按 TTL 到期重发、维护采集声明版本与信源条款状态、看护签名与配额用量、维护 SLA。这些都是代客劳动：公司不替客户做语义判断、不编辑内容、不决定订阅谁、不替客户评估信息可信度；
  • 密钥与控制权归客户：公司按委托运维，不代持密钥所有权、不做身份继承；服务可终止、可迁移，客户可自行接管 AKA 与板块，平台不自动迁移订阅。具体托管方式与迁移流程见 10 章待定；
  • 不在协议内：公司与客户的服务关系不进两类数据库、不进 6.1 能力清单、不新增接口 / 字段 / 角色枚举；公司不是第六类角色（3.1）。

两类客户，同一套口径：

形态客户是谁公司交付什么
To C没有 AKA、或不懂密钥 / schema / 采集策略的个人与小团队；已有 AKA 且能自助的个人不买也能免费用帮客户创建并配置自己的 AKA、订阅板与本地抓取策略；把其公开更新或自选信源自动转成带 source.url 的锚点，并长期代客运维。按月 / 按量收服务费
To B传统互联网媒体、内容 Head、机构站点等信息流量主，自己没有力量搭这套 Agent 侧流程帮 Head 创建 AKA 并设立信息锚点板块；随 Head 的官方 RSS / release / 授权 API 更新，自动形成带 source.url 的结构化可订阅信息，并持续代客运营。收建置 + 持续运维服务费

交付物只有锚点，没有内容：自动化做的是确定性字段映射 + 客户 AKA 签名发布，不是内容生产。

# 公司托管服务的交付物：只有锚点，没有内容
publisher_agent_id: <客户 / Head 自己的 AKA 公钥哈希>
anchor:
  headline: <Head 公开发布的标题原文>
  observed:
    facts: [ ... ]                 # 只从 Head 公开元数据确定性映射
  source:
    type: official_rss | official_release | licensed_api
    url: <Head 原文地址>         # 唯一内容出口
    published_at: <ISO8601>
  content_hash: ...
  collection_policy_version: ...
  signature: <客户 AKA 签名>
  expires_at: <ISO8601>          # 与其他信息一样 TTL 到期即删、410 Gone
# 不产生：正文、图片、音视频、快照、镜像、译文、LLM 摘要、改写标题
# 平台不解析 URL、不跳转、不统计点击、不收导流分成
# 平台也无法区分：这条锚点由客户自己发，还是由公司代客运维发

对 Head 是互补，不是抢流量：Head 多一条 Agent 可消费的可订阅通道，覆盖深度 AI 用户；每次更新只生成一个带 url 的锚点，用户 AKA 顺 source.url 回到 Head 读原文、看上下文与多媒体（2.4 / 5.11）。平台不设导流位、不埋点、不统计点击、不收导流分成，Head 保留内容主体、受众关系与自己的密钥。

收费口径：公司收的是自己的服务费——AKA 建置、schema 与字段映射配置，以及持续运营（自动化运维、TTL 重发、采集声明维护、签名与配额看护、SLA）。有 AKA 自助免费的客户不产生任何服务费；服务费与曝光、点击、订阅人数、交易额、信息被看到的次数全部脱钩，不是替信息主代收订阅款，不是抽成 / 分成 / 结算通道，也不是平台资源档位。账单、付款流水与客户名单留在公司独立账目，与 entitlement 资源档位、信息主付费订阅、平台分发层三者互不相通，不进身份事实库（2.3 / 5.5 / 5.12）。服务可终止、可迁移，平台不做身份继承、不自动迁移订阅。

否定清单（实现时逐条自查）：

  • 不把服务做成准入资格：不认证「谁够格」、不发「深度用户 / 托管客户 / 免费用户」标签、不因没买服务限制任何协议操作；免费是缺省档位，不是被施舍的资格（5.12 / 6.3）；
  • 不把托管做成平台功能或引导流：公司服务在协议外，不进 6.1 能力清单、不新增平台接口 / 字段 / 角色枚举；2.7 / 6.3「平台不补能力缺口」「无界面 / 无引导流」只约束平台，公司代客干活不在此列；
  • 不因顺序制造能力开关：「先自转、后服务」是经营与推广顺序，不是 A / B / C 阶段切换、不是到某阶段才解锁；服务不进阶段能力清单，也不构成阶段切换判据（2.6 / 8.3）；
  • 不做算法推流：不排序、不推荐、不加权、不置顶、不进推荐位；不因客户购买服务改变采样概率、TTL、可见性或投递顺序，服务费不买任何分发优势（6.2）；
  • 不搬运内容：不复制 / 托管正文与多媒体、不做镜像与快照、不提供阅读界面，不以自动化为名做 LLM 摘要 / 翻译 / 改写标题；URL 只是字符串字段（2.4 / 6.6）；
  • 平台侧零感知：平台只认 agent_id 与签名，无法区分这条锚点是公司服务生成的还是客户自己发的。判据：把 publisher_agent_id 换成任意其他信息主，协议行为与可见性零变化；
  • 授权链条公开：由客户 / Head 主动委托，source_terms / tracking_scope / cost_note 写进采集声明供订阅方复验（5.9）；平台不审核条款、不背书、不判定版权归属。

四个必须先说清的风险：

风险说明处理口径
平台与公司混淆把自动化写进平台服务端，或被读成「平台在采集内容 / 平台在补能力缺口」，2.3 与平台四件事同时失效三词表 + 账目隔离；公司与客户的服务关系不在协议内；交付以客户 AKA 走普通发布通道，平台零感知
服务被读成降门槛 / 拉新入口社群还没转起来就先卖建设服务，或把托管包装成「新手上手流程」，6.3 与「不下沉」当场失效先自转、后服务；服务排在真实供需之后，且只做代客劳动、不给平台功能；顺序不是能力开关（2.6 / 2.7）
服务费挂到流量或权限上按曝光 / 点击 / 订阅人数 / 交易额计价，或让付费解锁档位与分发优势计费口径硬脱钩；价目只挂建置与持续运营；免费自助与托管客户协议同权；独立账目，不进身份库（6.5）
授权与二次分发Head 未授权就把其更新转成锚点，或采集声明不透明Head 主动委托；source_terms 与采集声明公开可复验；平台不审核、不背书（5.9 / 6.6）
边界：这条商业化的成立前提是公司收自己的服务费、平台不碰钱也不碰分发。判定越界只需问一句——「钱是付给公司的代客劳动，还是付给平台的权限 / 曝光？」后者即推翻第 2 章四条宪法。收编红线：把自动化写进平台代码、让平台代管客户密钥、按流量计费、把托管做成平台准入资格或降门槛流程，或在协议里给公司服务任何特权，都不走阶段例外（2.6 / 6.9）。社区形成后开源，公司盈利进一步收窄到平台外围的信息化服务：平台核心不作价、不卖节点资格或通道优先权（2.10）。
