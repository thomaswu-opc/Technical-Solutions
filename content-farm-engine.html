01 · Positioning

不是 BIM 日报，而是可复用的内容生产底座。

Daily BIM News 只是第一个业务样本。真正沉淀的是一套面向垂直主题的信息检索、结构化整理、去重、排版、发布和通知自动化框架。

A

目标自然语言化

用户可以输入自然语言目标，也可以配置结构化选项。系统会清洗目标、合并参数，并生成可控 prompt。

B

搜索与抽取解耦

搜索引擎、LLM、爬虫和定向检索都通过 adapter 接入，避免业务流程被某个外部服务锁死。

C

末端只负责发送

Notion、语雀、Telegram、Webhook 等只是发布或通知末端，不参与业务查重，也不回流系统状态。

02 · Pipeline

从搜索到推流的可编排链路。

MVP 采用本地优先实现，保留微服务边界：gateway、pipeline、delivery、state store。后续可拆成独立服务。

01Intent

清洗自然语言目标，合并用户选项。

02Search

按 provider、范围、时间窗执行检索。

03Normalize

统一结果结构，形成标准 document。

04Dedupe

在内部 SQLite 与可观测列表中查重。

05Extract

调用 LLM adapter 生成结构化 item。

06Render

输出 Markdown 与结构化 JSON artifact。

07Deliver

发布到笔记软件，并发送通信通知。

03 · Boundary

把系统边界收敛，后续才好扩张。

查重、状态、可观测性留在系统内部；外部工具全部做 adapter；发布与通知不回流业务判断。

系统内部负责

  • 目标清洗与 prompt 生成。
  • 搜索结果标准化与 URL 级查重。
  • 结构化 JSON 与 Markdown artifact。
  • Pipeline run 状态、delivery record、duplicates 可观测列表。

外部 adapter 负责

  • Bing、Tavily、未来爬虫与定向检索。
  • OpenAI-compatible LLM 或本地模型。
  • Notion、语雀等笔记软件发布。
  • Telegram、Webhook 等通知渠道。
04 · Current Delivery

当前已经形成可测试的本地 MVP。

本地仓库已初始化 Git，包含 CLI/API、测试、配置 profile 和 adapter placeholder。真实外部能力可以逐个替换，而不改主流程。
